# PROVA — Flutter Frontend

Implements the four frontend modules from Figure H-1 (System Architecture):
Operations & Monitoring, Annotation Workspace, Evaluation & Records, Administration.

## First-time setup

You need the Flutter SDK installed locally (this scaffold's `lib/` and
`pubspec.yaml` were hand-written, not generated by `flutter create`, so you
need to generate the platform folders yourself):

```bash
# 1. Confirm Flutter is installed
flutter doctor

# 2. From the repo root, create a throwaway scaffold project just to get
#    the platform folders (android/, ios/, web/, etc.)
flutter create --org com.yourteam --project-name prova_app tmp_scaffold
cp -r tmp_scaffold/android tmp_scaffold/ios tmp_scaffold/web \
      tmp_scaffold/macos tmp_scaffold/linux tmp_scaffold/windows \
      flutter_app/
rm -rf tmp_scaffold

# 3. Install dependencies
cd flutter_app
flutter pub get

# 4. Connect Firebase (see /firebase/README.md for the project-side setup
#    first — you need an actual Firebase project before this step)
dart pub global activate flutterfire_cli
flutterfire configure
#    This overwrites lib/firebase_options.dart with real values.

# 5. Run
flutter run -d chrome --dart-define=BACKEND_BASE_URL=http://localhost:8000
```

## Module -> file map

| Figure H-1 box              | Route             | File                                                              |
|------------------------------|-------------------|--------------------------------------------------------------------|
| Operations & Monitoring      | `/operations`     | `lib/features/operations_monitoring/presentation/operations_screen.dart` |
| Annotation Workspace         | `/annotation`     | `lib/features/annotation_workspace/presentation/annotation_screen.dart`  |
| Evaluation & Records         | `/evaluation`     | `lib/features/evaluation_records/presentation/evaluation_screen.dart`    |
| Administration                | `/administration` | `lib/features/administration/presentation/administration_screen.dart`    |

Role-based visibility (Researcher/Operator vs Annotator vs Adjudicator, per
Figure H-2) is enforced in `lib/features/auth/domain/user_role.dart` and
consumed by `lib/core/widgets/app_shell.dart`.

## Talking to the backend

`lib/services/backend_api.dart` calls the Python FastAPI service in
`/backend`. Point it at a different URL with:

```bash
flutter run --dart-define=BACKEND_BASE_URL=https://your-deployed-backend
```

## Modularity notes

- Each `features/<module>/{data,domain,presentation}` folder is self-contained;
  a module never imports another module's `presentation/` files directly.
- Shared entities/services live in `lib/core` and `lib/services` only.
- Firestore collection names are centralized in
  `lib/services/firestore_paths.dart` — never hardcode a collection string
  elsewhere, so the schema stays a single source of truth with `/firebase`
  and `/backend`.
